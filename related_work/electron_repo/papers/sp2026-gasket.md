## 1. Problem, Gap & Hypothesis
Modern JavaScript applications increasingly delegate performance-critical work to native extensions (written in C, C++, or Rust) and to WebAssembly modules. This polyglot architecture imports native-code attack surface (memory- and type-unsafety) that becomes reachable through JavaScript interfaces. Effective cross-language security analysis — vulnerability detection, reachability analysis, attack-surface analysis, runtime protection — hinges on accurately identifying *bridges*: the JavaScript function objects that delegate execution to low-level code. The gap: existing static analyzers such as CHARON identify bridges by pattern-matching binding-framework APIs and native code, but (a) they cover only a subset of foreign-function-interface (FFI) pathways, so they *miss* bridges, and (b) they over-approximate the semantics of the frameworks they do support, producing *false positives*. The tools that depend on this bridge information (e.g., runtime sandboxes NATISAND and HODOR) are only as good as the bridge identification beneath them. Hypothesis: because *all* JS function objects — regardless of binding framework, source language, or runtime — are ultimately represented as uniform internal structures inside the JavaScript engine (V8), inspecting the engine's in-memory representation directly yields complete, false-positive-free bridge identification.

## 2. Methodology
GASKET is a dynamic, runtime-agnostic analysis tool. Its key mechanism: at runtime it exhaustively walks the loaded modules and extracts the memory addresses of the functions exposed within them, then reads V8's internal `JSFunction`/function-object structures to recover *which* native or WebAssembly function each high-level JavaScript function is bound to. Because it works at the engine level rather than at the binding-framework level, the same technique transparently handles bindings created with different frameworks (e.g., `node-addon-api`), implemented in different languages, and executed across different V8 embedders. The authors implement and demonstrate it on **Node.js, Deno, and Chromium**. To show real-world security value, GASKET is dropped in as a replacement for CHARON's static bridge-identification stage, feeding more complete bridge information into the same downstream vulnerability-detection and reachability machinery. The motivating example is the npm package `node-sqlite3`, whose C++ `BindParameter` wrongly assumes a parameter's `toString` is always a function; an attacker-supplied `{toString: <number>}` triggers a hard crash (DoS) when V8 invokes `ToString()` on it.

## 3. Experiments / Evaluation Setup — targets, dataset sizes, configs, what was measured
Three evaluation prongs: (1) **Bridge-identification accuracy** — applied to **20 packages spanning 10 different binding frameworks and runtime environments** (covering Node.js and Deno FFIs, "over 15" FFI variants discussed), measuring recall and false positives against ground truth. (2) **Vulnerability-detection uplift** — GASKET integrated into CHARON and run over **1,266 npm packages**, measuring how many additional bridges and vulnerable flows are recovered versus CHARON's native static identification. (3) **Supply-chain reachability** — a systematic study of **2,197 dependent packages** against **10 known vulnerabilities** in native extensions, measuring how often a dependent package actually *invokes* the vulnerable native function (true reachability) versus merely depending on the vulnerable version.

## 4. Results / Key Findings — concrete numbers
- **Perfect recall with zero false positives** across the 20-package / 10-framework benchmark — GASKET identifies every bridge and introduces none spuriously.
- Swapping CHARON's static stage for GASKET makes the combined system detect **2.5× more bridges**, which surfaces **54 vulnerable flows across 23 packages that prior work missed entirely**; of these, **19 are confirmed exploitable across 12 packages**.
- Reachability study: across **2,197 dependent packages** and **10 known native-extension vulnerabilities**, although many packages depend on a vulnerable native extension, only a **small fraction actually invoke the vulnerable function** — enabling precise prioritization and reduced alert fatigue.
- Tool released open-source (Apache-2.0) at github.com/gasket-tools/gasket.
