## 1. LMSM: LLM Security Framework Inspired by Linux Security Modules  🆕

- **저자**: XiuYu Zhang, Bonan Ruan, Junfeng Fang, An Zhang, Tat-Seng Chua, et al.
- **키워드**: `defense_mechanism`, `guardrail`, `sae`, `probing`, `serving_security`
- **출처**: HF Daily · arxiv recent
- **arxiv**: [2608.25697](https://arxiv.org/abs/2608.25697) (v1)
- **PDF**: [`./pdfs/2608.25697.pdf`](./pdfs/2608.25697.pdf)

**핵심 요약**:
LLM 배포 환경은 여러 겹의 방어를 쌓지만 악성 프롬프트는 여전히 이를 우회하며, SAE·프로브 같은 해석가능성 신호는 그 자체로 보안 통제가 아니어서 신호마다 캘리브레이션·정책·개입 코드를 따로 붙이는 통합 비용이 반복된다. 저자들은 리눅스 보안 모듈(LSM)의 관심사 분리를 LLM 서빙에 이식한 LMSM을 제안한다. 보안 백엔드가 캘리브레이션된 증거를 노출하고, 버전 관리되는 정책이 요청별 신뢰 컨텍스트 위에서 규칙을 평가하며, 별도의 게이트가 버퍼링된 출력의 릴리스를 인가하는 3단 구조다. 이로써 "중재의 정확성"과 "정책의 효과성"이 분리되어 백엔드·규칙·스케줄을 요청 처리 경로 재작성 없이 교체할 수 있다. HF Transformers와 연속 배칭 vLLM 위 프로토타입에서 SAE·트랜스코더 아티팩트와 태스크 특화 dense probe를 같은 기반에 얹고, 스케줄러 변동 속에서도 요청별 결정을 보존하며 다중 규칙을 선택적으로 합성 적용함을 보였다.

## 2. LongPIBench: A Long-Context Benchmark for Prompt Injection  🆕

- **저자**: Yupei Liu, Yuqi Jia, Neil Zhenqiang Gong, Jinyuan Jia
- **키워드**: `prompt_injection`, `safety_eval`, `long_context`, `benchmark`
- **출처**: arxiv recent
- **arxiv**: [2608.28411](https://arxiv.org/abs/2608.28411) (v1)
- **PDF**: [`./pdfs/2608.28411.pdf`](./pdfs/2608.28411.pdf)

**핵심 요약**:
기존 프롬프트 인젝션 벤치마크는 대부분 짧은 컨텍스트 입력에 집중해 있어, 실제 배포 환경에 가까운 장문 컨텍스트에서의 공격·방어는 거의 검증되지 않았고 그 결과 현행 방어의 효과가 크게 과대평가되어 왔다. 저자들은 논문 피어리뷰, 이력서 스크리닝, 코드 리뷰, 이메일 요약이라는 4개 현실 시나리오로 구성된 LongPIBench를 만들었다. 각 시나리오마다 합성 데이터셋과 실제 데이터셋을 함께 구축했고 컨텍스트 길이는 수천~수만 토큰에 이른다. 평가 결과 장문 설정에서는 단순한 휴리스틱 인젝션 공격조차 높은 성공률을 기록하며 SOTA 방어를 자주 우회했다. 즉 방어의 강건성이 컨텍스트 길이에 매우 취약하다는 점을 드러내는 진단용 벤치마크다.

## 3. ContextLeak: Exfiltrating LLM Agent Context via Malicious Tools  🆕

- **저자**: Yuqi Jia, Ruiqi Wang, Patrick Li, Yuepeng Hu, Peinian Li, et al.
- **키워드**: `agent_safety`, `agent_privacy`, `data_extraction`, `tool_poisoning`, `pii_leakage`
- **출처**: arxiv recent
- **arxiv**: [2608.27800](https://arxiv.org/abs/2608.27800) (v1)
- **PDF**: [`./pdfs/2608.27800.pdf`](./pdfs/2608.27800.pdf)

**핵심 요약**:
LLM 에이전트의 런타임 컨텍스트(사용자 프롬프트, 실행 경로, 도구 목록)가 외부로 유출되면 심각한 보안·프라이버시 피해가 발생하는데, 악성 도구를 통한 유출은 (1) 에이전트가 그 도구를 고르고 (2) 컨텍스트를 인자로 넘기며 (3) 도구 구현이 이를 공격자 엔드포인트로 전송하는 세 조건을 요구한다. 기존 연구는 (1)과 (3)에 집중해 정작 결정적인 (2)를 방치했다. ContextLeak은 도구의 **이름과 설명문**을 정교하게 조작해 에이전트가 도구를 선택하도록 유도할 뿐 아니라 자기 컨텍스트를 인자로 스스로 노출하게 만든다. 공격용 LLM이 이름·설명을 자동 생성하고, 다양한 시뮬레이션 컨텍스트를 가진 shadow user 집합 위에서 강화학습으로 미세조정된다. 핵심 기여는 컨텍스트 탈취 목적에 맞춘 보상 함수 설계로, 이를 통해 RL 기반 공격 최적화가 실제로 작동함을 보였다.

- **PDF**: [`./pdfs/2608.28099.pdf`](./pdfs/2608.28099.pdf)

**핵심 요약**:
추론 중 실시간 분류는 안전 필터링·행동 분석·모델 모니터링에 유용하지만, 현재 방식은 정확도와 효율 사이에서 양자택일을 강요한다. hidden-state 프로브는 빠르지만 단일 벡터만 보아 위치 간 상호작용을 못 잡고, 반대로 Llama Guard·Qwen Guard·LLM-as-judge나 전 토큰 은닉상태 풀링(MultiMax)은 정확하지만 비싸다. 저자들은 최신 LLM에 이미 들어 있는 **speculative decoding 모듈**을 시퀀스 분류기로 재활용한다. 대상 시퀀스 끝에 학습된 soft prompt를 덧붙이는 것만으로 분류기가 되며, speculative decoding 파이프라인에서는 KV 캐시가 이미 GPU에 올라와 있어 추가 비용이 사실상 없다. 4개 모델(Qwen3.5-4B/9B/27B, MiniCPM4.1-8B)·4개 태스크에서 이 작은 프로브가 zero-shot GPT-5.4-mini를 일관되게 앞섰고, 다국어 프롬프트 안전성에서는 전체 LLM을 돌리지 않고도 8B급 전용 안전 분류기와 동등하거나 그 이상이었다.

## 5. How Do Linear Probes Emerge? A Circuit-Tracing Framework with Concept-Targeted Attribution  🆕

- **저자**: Vedant Palit, Florent Draye, Terry Jingchen Zhang, Bernhard Schölkopf, Zhijing Jin
- **키워드**: `circuits`, `probing`, `feature_attribution`, `mechanistic_interpretability`, `transcoder`
- **출처**: arxiv recent
- **arxiv**: [2608.27510](https://arxiv.org/abs/2608.27510) (v1)
- **PDF**: [`./pdfs/2608.27510.pdf`](./pdfs/2608.27510.pdf)

**핵심 요약**:
트랜스코더 기반 attribution graph는 보통 "모델이 왜 특정 다음 토큰에 높은 확률을 주는가"를 설명하도록 학습되는데, 저자들은 목표를 **선형 프로브 방향**으로 바꾼 Concept-Targeted Attribution(CTA)을 제안한다. 그 결과 얻어지는 프로브 특화 회로는 해당 개념 표현이 왜 프롬프트 안에서 생겨나는지를, 그 개념이 생성 토큰으로 표출되는지와 무관하게 설명한다. Cross-Layer Transcoder를 써서 네 개의 표준 개념 범주에서 그래프 수준 특징이 프로브 정확도를 예측함을 보였고(ρ=0.91, R²=0.84), 국소 특징은 프롬프트별 분류를 이끄는 희소 요소를 짚어낸다. 인과적 ablation 결과 프로브 타깃 회로와 로짓 타깃 회로는 기능적으로 서로 다른 메커니즘을 포착한다 — 프로브 관련 특징을 제거하면 내부 개념 점수는 떨어지지만 생성 토큰은 대체로 유지되는 반면, 로짓 관련 특징 제거는 92~100%의 경우 생성 토큰을 바꾸면서 프로브 점수에는 거의 영향이 없다. 프로브의 "정확도"에서 "왜 작동하는가"로 넘어가는 프레임워크다.

## 6. Performative Privacy: When Differential Privacy Maximizes Utility  🆕

- **저자**: Uddalak Mukherjee, Edwige Cyffers, Yann Chevaleyre
- **키워드**: `differential_privacy`, `performative_learning`, `privacy_utility_tradeoff`
- **출처**: arxiv recent
- **arxiv**: [2608.28198](https://arxiv.org/abs/2608.28198) (v1)
- **PDF**: [`./pdfs/2608.28198.pdf`](./pdfs/2608.28198.pdf)

**핵심 요약**:
"프라이버시를 보호하면 신뢰가 유지되고 참여가 늘어 장기적으로 효용이 좋아진다"는 통념은 지금껏 형식화된 적이 없었다. 저자들은 배포가 이후 관측 데이터를 바꾸는 상황을 다루는 performative learning 틀과 프라이버시 학습을 결합해 **performative privacy** 개념을 도입한다. 데이터 유출이 향후 참여를 감소시키는 설정에서, 에이전트들이 평균 추정을 위해 반복적으로 데이터를 기여하되 자기 데이터가 새면 이탈하는 단순 모델을 분석한다. DP 메커니즘은 추정 노이즈와 미래 참여율 사이의 트레이드오프를 만든다. 이론적 동역학 분석과 수치 실험을 통해, 유출↔이탈 피드백 루프가 충분히 강하면 **유한한 프라이버시 예산이 비프라이빗 추정보다 장기 효용에서 더 낫다**는 것을 보인다. DP가 보호 장치일 뿐 아니라 장기 효용 관점에서도 최적일 수 있다는 첫 근거다.

## 7. REINS: Refusal-Enhanced Inhibitory Steering with Sparse Autoencoder Features  🆕

- **저자**: Kai-Xuan Ding, Hao-Xiang Xu, Ji-Hua Peng, Zi-Qi Chen, Jiaqi Wang, et al.
- **키워드**: `sae`, `activation_steering`, `jailbreak`, `alignment_robustness`, `refusal`
- **출처**: arxiv recent
- **arxiv**: [2608.28233](https://arxiv.org/abs/2608.28233) (v1)
- **PDF**: [`./pdfs/2608.28233.pdf`](./pdfs/2608.28233.pdf)

**핵심 요약**:
SAE steering은 재학습 없이 추론 시점에 LLM 행동을 조정하는 경량 경로이고, 희소·해석가능 특징을 노출하기에 유해 생성을 거부로 유도하는 안전 제어 인터페이스로 유망하다. 그러나 저자들은 복잡한 wrapper로 감싼 유해 프롬프트 앞에서는 기존 SAE steering이 무너진다는 점을 관찰했다. 이를 체계적으로 평가하려고 복잡한 wrapper가 붙은 유해 프롬프트 데이터셋 GUISE를 구축했고, 기존의 단일 방향 SAE steering은 안정적으로 거부를 만들어내지 못했다 — 유해 continuation 경로가 여전히 살아 있는 한 거부 강화만으로는 약하다는 뜻이다. 그래서 같은 SAE 특징 공간 안에서 **유해 continuation 특징을 억제하면서 동시에 안전 거부 특징을 강화**하는 REINS를 제안한다. GUISE 및 기타 데이터셋에서 기존 기법이 개입이 너무 약하거나 붕괴를 통한 겉보기 안전에 그친 반면, REINS는 유해 응답을 크게 줄이고 안전한 거부를 뚜렷이 늘리면서 일반 능력은 대체로 보존했다.

## 8. Memorization Is Not Extraction: Tight Differential-Privacy Bounds and Audit Blind Spots  🆕

- **저자**: Xujun Che, Depeng Xu, Shuhan Yuan
- **키워드**: `differential_privacy`, `data_extraction`, `memorization`, `privacy_audit`, `f-DP`
- **출처**: arxiv recent
- **arxiv**: [2608.27782](https://arxiv.org/abs/2608.27782) (v1)
- **PDF**: [`./pdfs/2608.27782.pdf`](./pdfs/2608.27782.pdf)

**핵심 요약**:
LLM 암기(memorization)는 서로 형식적 관계가 불분명한 여러 정의로 측정되는데, DP는 그 모두를 한꺼번에 막는 대리 지표처럼 취급되어 왔다. 저자들은 실무적으로 중요한 두 정의 — counterfactual memorization과 adaptive extraction — 의 **정확한 DP 상수**를 규명하고, 둘이 서로를 통제하지 못함을 보인다. f-DP 하에서 리스트 예산 m을 가진 임의의 adaptive extraction 프로토콜의 성공 확률은 oblivious baseline κ에 대해 1−f(κ) 이하로 묶이며 이 한계는 조밀한 baseline 집합 위에서 타이트하다. 즉 DP는 "사전에 비밀을 얼마나 잘 추측할 수 있는가"라는 임계까지만 추출을 균일하게 통제한다. min-entropy는 이 baseline을 분포 무관하게 인증하고, 암기 측면에서 f-DP는 임의의 유계 점수의 counterfactual memorization을 advantage 함수 η(f)(순수 DP에서는 tanh(ε/2))로 상한한다. 중복 사본 k≥2일 때 흔히 쓰는 ε↦kε 대입(tanh(kε/2))은 달성 불가능하며 정확한 상수는 닫힌 형태의 계단 함수임을 밝힌다. **DP 감사(audit)가 어디서 눈이 머는지**를 정량화한 결과다.

## 9. GRACE: Gradient-guided Coreset Selection for LLM Unlearning  🆕

- **저자**: Praveen Bushipaka, Andrea D'Angelo, Lucia Passaro, Tommaso Cucinotta
- **키워드**: `unlearning`, `coreset_selection`, `gradient_matching`, `data_selection`
- **출처**: arxiv recent
- **arxiv**: [2608.28361](https://arxiv.org/abs/2608.28361) (v1)
- **PDF**: [`./pdfs/2608.28361.pdf`](./pdfs/2608.28361.pdf)

**핵심 요약**:
LLM 머신 언러닝 연구는 forget/retain 집합이 미리 주어진다고 가정하지만, 현실의 삭제 요청은 원치 않는 행동의 예시 몇 개만 제공하는 경우가 많아 이질적 코퍼스로부터 두 집합을 **추론**해내야 한다. GRACE는 이 데이터 선택 문제를 정면으로 다루는 gradient 기반 coreset 선택 기법이다. 먼저 문제 행동을 유발하는 seed 예시들로부터 forget 방향을 계산하고, non-negative orthogonal matching pursuit으로 그 방향을 그래디언트로 근사하는 소형 forget coreset을 고른다. 모델 효용 보존을 위해 retain 예시는 forget 방향을 사영 제거한 잔여 그래디언트 공간에서 clustered OMP로 선택한다. 두 개 타깃 도메인 × 두 개 모델 계열 × 네 개 언러닝 알고리즘에 걸쳐, GRACE는 forget 품질을 비슷하게 유지하면서 모델 효용을 개선했고 특히 기존 그래디언트 기반 선택 대비 이득이 일관적이었다.

**핵심 요약**:
모델이 보는 것은 전부 토큰이다 — 서빙 스택은 각 span이 사용자 입력인지 도구 출력인지 지시문인지 알지만 모델은 그걸 스스로 추적해야 하고, 텍스트는 무엇처럼도 보이게 쓸 수 있으므로 혼동이 발생한다. 프롬프트 인젝션은 바로 이 span 정체성 혼동을 악용하는 공격이다. 저자는 span 정체성을 텍스트 바깥 채널로 전달하는 **Semantic Overlays**를 제안한다. 동결된 모델의 residual stream에 대해 선택된 prefill 위치에 적용되는 작은 학습형 어댑터로, 토큰으로는 복제할 수 없는 out-of-band 주석 채널을 만든다. 기존 steering vector와 달리 학습 가능하고 적응적이며 선택적으로 적용된다. 오버레이는 합성 가능하고 원문 내용을 투명하게 읽게 하며 복잡한 페이로드(모델이 따르는 명령까지)를 실을 수 있는데, span을 "실행 불가"로 표시하는 오버레이는 프롬프트 인젝션 계열 전반을 방어한다.

**v1 → v2 변경점**: abstract 수준에서는 문장 다듬기 위주의 편집(예: "potentially dangerous"→"dangerous", 프로그래밍 언어 재작성 예시 문장 축약)으로, 방법론이나 주장의 실질적 변경은 확인되지 않았다.
